Capítulos
    Capítulo 1

    ¿Qué es una base de datos?

    Una base de datos es un conjunto organizado de información guardada de forma que se pueda consultar, modificar y proteger con facilidad. Tu lista de contactos, el inventario de una tienda, las notas de un colegio o los movimientos de tu cuenta del banco viven en bases de datos.

    Piensa en un archivador de oficina: cada cajón es una tabla (clientes, productos, pedidos), cada ficha es una fila y cada dato de la ficha (nombre, teléfono, ciudad) es una columna. La diferencia es que aquí no buscas a mano: le pides los datos al sistema con un lenguaje llamado SQL y él los encuentra por ti en milisegundos, aunque haya millones de fichas.

    El programa que administra la base de datos se llama SGBD (Sistema Gestor de Bases de Datos, en inglés DBMS). Es el "bibliotecario": recibe tus peticiones, comprueba que tengas permiso, busca los datos, evita que dos personas se pisen al escribir a la vez y garantiza que nada se pierda si se va la luz.

    Relacionales (SQL)

    Datos en tablas con columnas fijas, unidas por claves. Ejemplos: PostgreSQL, MySQL, MariaDB, SQLite, SQL Server, Oracle. Son las más usadas y las que aprendemos aquí.

    No relacionales (NoSQL)

    Guardan documentos (MongoDB), pares clave-valor (Redis), columnas anchas (Cassandra) o grafos (Neo4j). Útiles cuando la estructura cambia mucho o la escala es enorme.

    ¿Y por qué no un Excel?

    Una hoja de cálculo no impide datos inválidos, no aguanta a cien personas escribiendo a la vez, no tiene permisos finos y se vuelve lenta con millones de filas.

    Capítulo 2
    Conceptos clave: tablas, filas, claves
    
      
    Toda la página usa la misma base de datos de ejemplo: una pequeña tienda de tecnología con tres tablas. Puedes abrirla cuando quieras en el Laboratorio SQL (botón abajo a la derecha).
    

      
    
        
    Tabla
    Colección de datos sobre una sola cosa: clientes, productos, pedidos.
    
        
    Fila (registro)
    Un elemento concreto: el cliente «Ana Torres».
    
        
    Columna (campo)
    Una característica con un tipo de dato fijo: ciudad es texto, precio es número.
    
        
    Clave primaria (PK)
    Columna que identifica cada fila de forma única. No se repite y no puede ser NULL. Ej.: clientes.id.
    
        
    Clave foránea (FK)
    Columna que apunta a la PK de otra tabla y crea la relación. Ej.: pedidos.cliente_id → clientes.id.
    
        
    NULL
    Significa «desconocido» o «sin valor». No es cero ni texto vacío. Se compara con IS NULL, nunca con =.

    Restricciones (reglas que protegen los datos)
    
      
      
        
    • PRIMARY KEY: identificador único de la fila.
      • 
        
    • FOREIGN KEY ... REFERENCES: el valor debe existir en la otra tabla.
      • 
        
    • NOT NULL: la columna es obligatoria.
      • 
        
    • UNIQUE: no se permiten valores repetidos (por ejemplo, el email).
      • 
        
    • DEFAULT: valor que se pone si no indicas otro.
      •

      • 
      
    

      
    Tipos de relación
    
      
    
        
    Uno a uno (1:1)
    Una persona tiene un pasaporte. Poco frecuente; a veces se fusiona en una sola tabla.
    
        
    Uno a muchos (1:N)
    Un cliente hace muchos pedidos. La FK va en el lado «muchos» (pedidos.cliente_id).
    
        
    Muchos a muchos (N:M)
    Alumnos y cursos. Necesita una tabla intermedia, por ejemplo inscripciones(alumno_id, curso_id).
    
      
    
      
    
    
    

    
    
    
      
    Capítulo 3
    SQL y sus cinco familias de comandos
    
      
    SQL (Structured Query Language) es el lenguaje estándar para hablar con bases de datos relacionales. Es declarativo: describes qué quieres, no cómo buscarlo; de eso se encarga el optimizador. Los comandos se agrupan según su función:
    
      
    
        
    
          
    FamiliaSignificadoPara qué sirveComandos
    
          
            
    DDLData Definition LanguageCrear y cambiar la estructuraCREATE, ALTER, DROP, TRUNCATE, RENAME
    
            
    DMLData Manipulation LanguageMeter, cambiar y borrar datosINSERT, UPDATE, DELETE
    
            
    DQLData Query LanguageConsultar datosSELECT
    
            
    DCLData Control LanguagePermisos de usuariosGRANT, REVOKE
    
            
    TCLTransaction Control LanguageControlar transaccionesBEGIN, COMMIT, ROLLBACK, SAVEPOINT
    
              
        
    
      
    
      
    Reglas de escrituraLas palabras clave no distinguen mayúsculas (select = SELECT), pero se escriben en mayúsculas por costumbre. Cada sentencia termina en ;. El texto va entre comillas simples 'así'. Los comentarios empiezan con --.
    
      
    DialectosCada motor añade variaciones al estándar. En esta página se ejecuta SQLite; cuando un comando cambia en MySQL, PostgreSQL o SQL Server te lo indico.
    
      
    
    
    

    
    
    
      
    Capítulo 4
    Los comandos más importantes
    
      
    Estos son los comandos que usarás el 90 % del tiempo. Cada ejemplo tiene el botón Probar: lo carga en el laboratorio para que lo ejecutes y lo modifiques.
    

      
    Crear y cambiar la estructura (DDL)
    
      
    
        
    
          
    CREATE TABLEDDL
    
          
    Crea una tabla nueva con sus columnas, tipos y restricciones.
    
          
    CREATE TABLE nombre (columna TIPO restricciones, ...);
    
          
    CREATE TABLE empleados (
  id      INTEGER PRIMARY KEY,
  nombre  TEXT NOT NULL,
  puesto  TEXT DEFAULT 'Vendedor',
  salario DECIMAL(10,2) CHECK (salario > 0),
  email   TEXT UNIQUE
);
    
        
    
        
    
          
    ALTER TABLEDDL
    
          
    Modifica una tabla existente: añadir, renombrar o quitar columnas.
    
          
    ALTER TABLE clientes ADD COLUMN telefono TEXT;
ALTER TABLE clientes RENAME COLUMN telefono TO movil;
SELECT * FROM clientes LIMIT 3;
    
        
    
        
    
          
    DROP TABLEDDL
    
          
    Elimina la tabla completa: estructura y datos. No hay papelera. IF EXISTS evita el error si no existe.
    
          
    DROP TABLE IF EXISTS empleados;
    
        
    
        
    
          
    CREATE DATABASEDDL
    
          
    Crea una base de datos nueva en el servidor (MySQL, PostgreSQL, SQL Server). En SQLite cada archivo ya es una base de datos, así que no existe.
    
          
    CREATE DATABASE tienda;
USE tienda;          -- MySQL: elegir la base activa
-- PostgreSQL: \c tienda
    
        
    
      
    

      
    Meter, cambiar y borrar datos (DML)
    
      
    
        
    
          
    INSERT INTODML
    
          
    Añade filas nuevas. Indica siempre las columnas: así no dependes del orden de la tabla.
    
          
    INSERT INTO clientes (nombre, ciudad, email, fecha_registro)
VALUES ('Elena Vidal', 'Madrid', 'elena@correo.com', '2024-09-01');

-- Varias filas a la vez
INSERT INTO productos (nombre, categoria, precio, stock)
VALUES ('Alfombrilla', 'Accesorios', 12.00, 50),
       ('Hub USB', 'Accesorios', 19.90, 20);

SELECT * FROM productos ORDER BY id DESC LIMIT 3;
    
        
    
        
    
          
    UPDATEDML
    
          
    Cambia valores de filas existentes. El WHERE decide qué filas se tocan; sin él cambian todas.
    
          
    UPDATE productos
SET precio = precio * 0.90, stock = stock + 5
WHERE categoria = 'Audio';

SELECT nombre, precio, stock FROM productos WHERE categoria = 'Audio';
    
        
    
        
    
          
    DELETEDML
    
          
    Borra filas. Igual que UPDATE: sin WHERE borra todo el contenido de la tabla.
    
          
    DELETE FROM pedidos WHERE fecha < '2024-07-05';
SELECT COUNT(*) AS pedidos_restantes FROM pedidos;
    
        
    
      
    

      
    Consultar datos (DQL)
    
      
    
        
    
          
    SELECT … FROMDQL
    
          
    Lee datos. * significa «todas las columnas». AS pone un alias, y puedes calcular columnas nuevas.
    
          
    SELECT nombre, precio, precio * 1.21 AS precio_con_iva
FROM productos;
    
        
    
        
    
          
    WHEREFILTRO
    
          
    Filtra filas con condiciones. Operadores: =, <> (distinto), >, <, >=, <=, combinados con AND, OR, NOT.
    
          
    SELECT nombre, categoria, precio
FROM productos
WHERE categoria = 'Periféricos' AND precio < 50;
    
        
    
        
    
          
    IN · BETWEEN · LIKE · IS NULLFILTRO
    
          
    IN compara con una lista; BETWEEN con un rango (incluye los extremos); LIKE busca patrones (% = cualquier cantidad de caracteres, _ = exactamente uno); IS NULL detecta valores vacíos.
    
          
    SELECT nombre, ciudad FROM clientes WHERE ciudad IN ('Lima', 'Bogotá');
SELECT nombre, precio FROM productos WHERE precio BETWEEN 20 AND 40;
SELECT nombre FROM clientes WHERE nombre LIKE '%ez';
SELECT nombre FROM clientes WHERE email IS NULL;
    
        
    
        
    
          
    ORDER BY · LIMIT · DISTINCTDQL
    
          
    ORDER BY ordena (ASC ascendente por defecto, DESC descendente). LIMIT corta el número de filas. DISTINCT quita duplicados.
    
          
    SELECT nombre, precio FROM productos ORDER BY precio DESC LIMIT 3;
SELECT DISTINCT ciudad FROM clientes ORDER BY ciudad;
    
          
    Ojo con el dialectoLIMIT 3 funciona en MySQL, PostgreSQL y SQLite. En SQL Server es SELECT TOP 3 ... y en Oracle o el estándar SQL es FETCH FIRST 3 ROWS ONLY.
    
        
    
        
    
          
    CASEEXPRESIÓN
    
          
    Un «si… entonces…» dentro de la consulta.
    
          
    SELECT nombre, stock,
  CASE
    WHEN stock = 0 THEN 'Agotado'
    WHEN stock < 10 THEN 'Pocas unidades'
    ELSE 'Disponible'
  END AS estado
FROM productos;

    Capítulo 5
    Agrupar y resumir datos
    
      
    Las funciones de agregado convierten muchas filas en un solo valor: COUNT (cuenta), SUM (suma), AVG (promedio), MIN y MAX. Con GROUP BY calculas ese resumen por cada grupo, y con HAVING filtras los grupos.
    
      
    
        
    
          
    COUNT · SUM · AVG · MIN · MAXAGREGADO
    
          
    SELECT COUNT(*)      AS productos,
       SUM(stock)    AS unidades,
       AVG(precio)   AS precio_medio,
       MIN(precio)   AS mas_barato,
       MAX(precio)   AS mas_caro
FROM productos;
    
        
    
        
    
          
    GROUP BY · HAVINGAGREGADO
    
          
    WHERE filtra filas antes de agrupar; HAVING filtra grupos después.
    
          
    SELECT categoria, COUNT(*) AS cantidad, ROUND(AVG(precio), 2) AS promedio
FROM productos
WHERE stock > 0
GROUP BY categoria
HAVING COUNT(*) >= 2
ORDER BY promedio DESC;

    Capítulo 6
    Unir tablas con JOIN
    
      
    Los datos están repartidos en varias tablas para no repetirlos. JOIN los vuelve a juntar usando las claves: «dame cada pedido junto al nombre de su cliente».
    
      
    
        
    
          
    TipoQué devuelveEn la tienda
    
          
            
    INNER JOINSolo las filas que coinciden en ambas tablasClientes que tienen pedidos (7 clientes)
    
            
    LEFT JOINTodas las filas de la izquierda; si no hay pareja, la derecha sale NULLTodos los clientes, Diego aparece con pedido NULL
    
            
    RIGHT JOINLo contrario: todas las de la derechaSe suele reescribir como LEFT JOIN invirtiendo tablas
    
            
    FULL OUTER JOINTodas las filas de ambas tablasNo existe en MySQL (se simula con UNION)
    
            
    CROSS JOINTodas las combinaciones posibles (producto cartesiano)8 clientes × 10 productos = 80 filas
    
              
        
    
      
    
      
    
        
    
          
    INNER JOINDQL
    
          
    Los alias cortos (c, p, pr) ahorran escritura y evitan ambigüedad cuando dos tablas tienen una columna con el mismo nombre (id).
    
          
    SELECT p.id, c.nombre AS cliente, pr.nombre AS producto, p.cantidad
FROM pedidos p
INNER JOIN clientes  c  ON c.id  = p.cliente_id
INNER JOIN productos pr ON pr.id = p.producto_id
ORDER BY p.id;
    
        
    
        
    
          
    LEFT JOINDQL
    
          
    SELECT c.nombre, COUNT(p.id) AS num_pedidos
FROM clientes c
LEFT JOIN pedidos p ON p.cliente_id = c.id
GROUP BY c.id, c.nombre
ORDER BY num_pedidos DESC;
    
        
    
        
    
          
    UNION · UNION ALLCONJUNTOS
    
          
    Apila resultados de dos consultas con las mismas columnas. UNION quita duplicados; UNION ALL los deja (y es más rápido).
    
          
    SELECT ciudad FROM clientes WHERE ciudad LIKE 'B%'
UNION
SELECT ciudad FROM clientes WHERE ciudad LIKE 'M%';

    Capítulo 7
    Subconsultas, vistas e índices
    
      
    
        
    
          
    SubconsultaDQL
    
          
    Una consulta dentro de otra. Puede ir en el WHERE, en el FROM o en el SELECT. EXISTS comprueba si la subconsulta devuelve alguna fila.
    
          
    -- Productos que nadie ha comprado
SELECT nombre FROM productos
WHERE id NOT IN (SELECT producto_id FROM pedidos);

-- Clientes que han comprado algo de Audio
SELECT nombre FROM clientes c
WHERE EXISTS (
  SELECT 1 FROM pedidos p JOIN productos pr ON pr.id = p.producto_id
  WHERE p.cliente_id = c.id AND pr.categoria = 'Audio'
);
    
        
    
        
    
          
    WITH (CTE)DQL
    
          
    Una «tabla temporal con nombre» solo para esa consulta. Hace legibles las consultas largas.
    
          
    WITH gasto AS (
  SELECT p.cliente_id, SUM(p.cantidad * pr.precio) AS total
  FROM pedidos p JOIN productos pr ON pr.id = p.producto_id
  GROUP BY p.cliente_id
)
SELECT c.nombre, ROUND(g.total, 2) AS total
FROM gasto g JOIN clientes c ON c.id = g.cliente_id
WHERE g.total > 300;
    
        
    
        
    
          
    CREATE VIEWDDL
    
          
    Guarda una consulta con nombre y úsala como si fuera una tabla. No copia los datos: se recalcula cada vez.
    
          
    CREATE VIEW IF NOT EXISTS sin_stock AS
SELECT id, nombre, categoria FROM productos WHERE stock = 0;

SELECT * FROM sin_stock;
    
        
    
        
    
          
    CREATE INDEXDDL
    
          
    Un índice es como el índice de un libro: el motor salta directo a las filas sin leer la tabla entera. Acelera búsquedas y JOIN, pero ocupa espacio y hace un poco más lentos los INSERT y UPDATE. Crea índices en columnas que filtras o unes a menudo.
    
          
    CREATE INDEX IF NOT EXISTS idx_clientes_ciudad ON clientes(ciudad);

-- Pregunta al motor cómo va a ejecutar la consulta
EXPLAIN QUERY PLAN
SELECT * FROM clientes WHERE ciudad = 'Lima';

    Capítulo 8
    Transacciones, ACID y permisos
    
      
    Una transacción agrupa varias operaciones que deben ocurrir todas o ninguna. El ejemplo clásico es una transferencia: restar dinero de una cuenta y sumarlo en otra. Si la segunda falla, la primera debe deshacerse.
    
      
    
        
    A · Atomicidad
    Todo o nada. Si algo falla, se deshace completa.
    
        
    C · Consistencia
    La base pasa de un estado válido a otro válido, respetando todas las reglas.
    
        
    I · Aislamiento
    Transacciones simultáneas no ven los cambios a medias de las otras.
    
        
    D · Durabilidad
    Tras el COMMIT, los cambios sobreviven a un apagón o un fallo.
    
      
    
      
    
        
    
          
    BEGIN · COMMIT · ROLLBACKTCL
    
          
    BEGIN TRANSACTION;
UPDATE productos SET stock = stock - 2 WHERE id = 5;
INSERT INTO pedidos (cliente_id, producto_id, cantidad, fecha)
VALUES (8, 5, 2, '2024-09-10');
COMMIT;      -- confirma los dos cambios juntos

BEGIN TRANSACTION;
DELETE FROM pedidos;   -- ¡uy!
ROLLBACK;    -- deshace el borrado

SELECT COUNT(*) AS pedidos FROM pedidos;
    
        
    
        
    
          
    SAVEPOINTTCL
    
          
    Un punto de guardado dentro de la transacción: puedes volver a él sin deshacer todo.
    
          
    BEGIN;
UPDATE productos SET precio = 50 WHERE id = 1;
SAVEPOINT antes_de_borrar;
DELETE FROM productos WHERE id = 6;
ROLLBACK TO antes_de_borrar;   -- el borrado se deshace, el UPDATE sigue
COMMIT;
SELECT id, nombre, precio FROM productos WHERE id IN (1, 6);
    
        
    
        
    
          
    GRANT · REVOKEDCL
    
          
    Dan y quitan permisos. SQLite no tiene usuarios, así que esto se usa en MySQL, PostgreSQL, SQL Server u Oracle. Principio básico: cada usuario con el mínimo permiso que necesita.
    
          
    -- PostgreSQL / MySQL
CREATE USER analista WITH PASSWORD 'clave_segura';   -- MySQL: IDENTIFIED BY
GRANT SELECT ON clientes TO analista;
GRANT SELECT, INSERT, UPDATE ON pedidos TO analista;
REVOKE UPDATE ON pedidos FROM analista;
    
          
    No se ejecuta en el laboratorio (SQLite no maneja usuarios).

    Capítulo 9
    Errores, excepciones y trampas comunes
    
      
    Aquí está lo que casi nadie explica al principio: los casos en los que un comando no hace lo que esperas, los errores que lanza el motor y cómo capturarlos. Prueba los ejemplos marcados como mal en el laboratorio para ver el error real.
    

      
    
        
    1. UPDATE o DELETE sin WHERE
    
        
    No da error: simplemente modifica o borra todas las filas. Es el accidente más famoso de SQL.
    
        
    
          
    mal
    UPDATE clientes SET ciudad = 'Lima';
    
          
    bien
    -- primero mira qué vas a cambiar
SELECT * FROM clientes WHERE id = 4;
UPDATE clientes SET ciudad = 'Lima' WHERE id = 4;
    
        
    
        
    Truco: escribe el WHERE primero, prueba con SELECT, y trabaja dentro de una transacción para poder hacer ROLLBACK. En MySQL, SET SQL_SAFE_UPDATES = 1; bloquea UPDATE y DELETE sin WHERE por clave.
    
      
    

      
    
        
    2. Comparar con NULL usando =
    
        
    NULL = NULL no es verdadero: es desconocido. Por eso WHERE email = NULL devuelve cero filas sin avisar.
    
        
    
          
    mal
    SELECT nombre FROM clientes WHERE email = NULL;
    
          
    bien
    SELECT nombre FROM clientes WHERE email IS NULL;
-- y para valores por defecto:
SELECT nombre, COALESCE(email, 'sin email') AS email FROM clientes;
    
        
    
        
    Variante peligrosa: NOT IN (...) con un NULL dentro de la lista devuelve vacío. Usa NOT EXISTS en su lugar.
    
      
    

      
    
        
    3. Usar un agregado en el WHERE
    
        
    El WHERE se evalúa antes de agrupar, así que todavía no existe COUNT(*).
    
        
    
          
    mal
    SELECT ciudad, COUNT(*) FROM clientes
WHERE COUNT(*) > 1
GROUP BY ciudad;
    
          
    bien
    SELECT ciudad, COUNT(*) FROM clientes
GROUP BY ciudad
HAVING COUNT(*) > 1;
    
        
    
      
    

      
    
        
    4. Columnas sin agrupar en el SELECT
    
        
    Con GROUP BY, cada columna del SELECT debe estar agrupada o dentro de un agregado. PostgreSQL y SQL Server lanzan error («column must appear in the GROUP BY clause»). MySQL con ONLY_FULL_GROUP_BY también. SQLite lo permite y devuelve un valor cualquiera del grupo, que es aún más peligroso porque no avisa.
    
        
    
          
    mal
    SELECT categoria, nombre, MAX(precio)
FROM productos GROUP BY categoria;
    
          
    bien
    SELECT categoria, MAX(precio) AS precio_max
FROM productos GROUP BY categoria;
    
        
    
      
    

      
    
        
    5. DELETE, TRUNCATE y DROP no son lo mismo
    
        
    
          
    
            
    ComandoQué borra¿WHERE?¿Se puede deshacer?Velocidad
    
            
              
    DELETEFilas (todas o algunas)SíSí, dentro de una transacciónLento en tablas enormes (fila a fila)
    
              
    TRUNCATETodas las filas; deja la estructura y reinicia los contadoresNoEn PostgreSQL sí dentro de transacción; en MySQL y Oracle noMuy rápido
    
              
    DROPLa tabla entera: estructura, datos, índicesNoNormalmente noInmediato
    
                
          
    
        
    
        
    SQLite no tiene TRUNCATE: DELETE FROM tabla; sin WHERE hace lo mismo.
    
      
    

      
    
        
    6. Violaciones de restricciones
    
        
    Cuando un dato rompe una regla, el motor rechaza la sentencia completa y lanza un error. Cada motor tiene su mensaje, pero el estándar define códigos SQLSTATE que te sirven para reconocerlos en cualquier lenguaje de programación.
    
        
    
          
    
            
    ErrorSQLSTATEMensaje típicoPruébalo
    
            
              
    Clave duplicada23505MySQL: Duplicate entry '1' for key 'PRIMARY' (1062) · SQLite: UNIQUE constraint failed
    
              
    Clave foránea inexistente23503MySQL: Cannot add or update a child row (1452) · SQLite: FOREIGN KEY constraint failed
    
              
    Campo obligatorio vacío23502PostgreSQL: null value in column violates not-null constraint · SQLite: NOT NULL constraint failed
    
              
    Condición CHECK23514SQLite: CHECK constraint failed
    
              
    Error de sintaxis42601syntax error at or near ...
    
              
    Tabla o columna no existe42P01 / 42703no such table · no such column
    
                
          
    
        
    
        
    También existe la eliminación en cascada: FOREIGN KEY (cliente_id) REFERENCES clientes(id) ON DELETE CASCADE borra los pedidos al borrar el cliente. Sin ella, borrar un cliente con pedidos da error 23503.
    
      
    

      
    
        
    7. Capturar excepciones en el propio motor
    
        
    En procedimientos almacenados puedes atrapar el error, deshacer la transacción y reaccionar. La sintaxis cambia según el motor (no se ejecutan en el laboratorio):
    
        
    
          
    SQL Server · TRY…CATCH
    BEGIN TRY
  BEGIN TRANSACTION;
  UPDATE cuentas SET saldo = saldo - 100 WHERE id = 1;
  UPDATE cuentas SET saldo = saldo + 100 WHERE id = 2;
  COMMIT;
END TRY
BEGIN CATCH
  ROLLBACK;
  SELECT ERROR_NUMBER(), ERROR_MESSAGE();
END CATCH;
    
          
    PostgreSQL · PL/pgSQL EXCEPTION
    DO $$
BEGIN
  INSERT INTO clientes (id, nombre) VALUES (1, 'Repetido');
EXCEPTION
  WHEN unique_violation THEN
    RAISE NOTICE 'Ese id ya existe';
END $$;
    
          
    MySQL · DECLARE HANDLER
    CREATE PROCEDURE alta_cliente(IN p_nombre VARCHAR(80))
BEGIN
  DECLARE EXIT HANDLER FOR SQLEXCEPTION
  BEGIN
    ROLLBACK;
    SELECT 'Falló el alta' AS mensaje;
  END;
  START TRANSACTION;
  INSERT INTO clientes (nombre) VALUES (p_nombre);
  COMMIT;
END;
    
          
    SQLite · conflicto controlado
    -- no falla: ignora la fila repetida
INSERT OR IGNORE INTO clientes (id, nombre) VALUES (1, 'Repetido');
-- "upsert": si existe, actualiza
INSERT INTO clientes (id, nombre, ciudad) VALUES (8, 'Diego Morales', 'Cusco')
ON CONFLICT(id) DO UPDATE SET ciudad = excluded.ciudad;
SELECT * FROM clientes WHERE id IN (1, 8);
    
        
    
        
    MySQL usa INSERT IGNORE y ON DUPLICATE KEY UPDATE; PostgreSQL usa ON CONFLICT igual que SQLite.
    
      
    

      
    
        
    8. Otras sorpresas
    
        
      
          
    • División entera: en PostgreSQL, SQL Server y SQLite, 5 / 2 da 2. Escribe 5.0 / 2 o CAST(5 AS DECIMAL) / 2. (MySQL sí devuelve 2.5.)
      • 
          
    • Comillas: simples para texto ('Lima'). Las dobles son para nombres de columnas en PostgreSQL y el estándar; en MySQL se usan acentos graves `tabla`.
      • 
          
    • Mayúsculas en los datos: 'lima' = 'Lima' es falso en PostgreSQL y SQLite, pero verdadero en MySQL por su collation habitual.
      • 
          
    • Autoincremento: MySQL AUTO_INCREMENT, PostgreSQL SERIAL o GENERATED ALWAYS AS IDENTITY, SQL Server IDENTITY(1,1), SQLite INTEGER PRIMARY KEY.
      • 
          
    • Fechas como texto: guarda siempre en formato AAAA-MM-DD; con DD/MM/AAAA la ordenación alfabética sale mal.
      • 
        
    
      
    

      
    
        
    9. Inyección SQL: el error de seguridad nº 1
    
        
    Si construyes la consulta pegando texto que escribe el usuario, alguien puede escribir SQL en lugar de un nombre. Usa siempre consultas parametrizadas: el motor trata el dato como dato, nunca como código.
    
        
    
          
    mal (Python)
    sql = "SELECT * FROM clientes WHERE nombre = '" + nombre + "'"
# nombre = "x' OR '1'='1"  → devuelve TODOS los clientes
    
          
    bien (Python)
    cursor.execute(
  "SELECT * FROM clientes WHERE nombre = ?",
  (nombre,)
)
    
        
    
      
    
      
    
    
    

    
    
    
      
    Capítulo 10
    Diseñar bien: normalización
    
      
    Normalizar es repartir los datos en tablas para que cada dato viva en un solo lugar. Así evitas inconsistencias: si el email de Ana está copiado en 30 pedidos y lo cambias en 29, ya tienes un problema.
    
      
    Partimos de una tabla mal diseñada:
    
      
    
        
    
          
    pedidoclienteciudad_clienteproductos
    
          
            
    1Ana TorresMadridTeclado, Auriculares
    
            
    2Ana TorresMadridPortátil
    
            
    3Luis PérezBogotáPortátil, Cable USB-C
    
              
        
    
      
    
      
    
        
    1FN · Primera forma normal
    Cada celda guarda un solo valor (nada de «Teclado, Auriculares») y no hay grupos repetidos. Solución: una fila por producto del pedido.
    
        
    2FN · Segunda forma normal
    Cumple 1FN y cada columna depende de la clave completa, no de una parte. Si la clave es (pedido, producto), el nombre del cliente depende solo del pedido: sácalo a otra tabla.
    
        
    3FN · Tercera forma normal
    Cumple 2FN y ninguna columna depende de otra columna que no sea clave. ciudad_cliente depende del cliente, no del pedido: va en la tabla clientes.
    
      
    
      
    El resultado es justo la tienda que usas en el laboratorio: clientes, productos y pedidos unidos por claves. A veces, en sistemas de informes, se desnormaliza a propósito para leer más rápido, pero siempre sabiendo por qué.
    
      
    Pasos para diseñar una base de datos1) Lista las cosas del mundo real (entidades): clientes, productos, pedidos. 2) Lista sus atributos. 3) Elige la clave primaria de cada una. 4) Define las relaciones (1:N, N:M) y pon las claves foráneas. 5) Revisa 1FN, 2FN y 3FN. 6) Añade restricciones e índices.
